# Архитектура

Проект независим от WolfMoon и не обращается к его папке во время запуска.
Из WolfMoon адаптированы парсер JVM-классов, интерпретатор CLDC, объектная память,
базовый MIDP raster bridge и оболочка RMS. Оптимизации, привязанные к классам и
игровым правилам WolfMoon, не переносились. Атласы системного шрифта из прошлого
проекта относятся к платформенному слою; проверенные экраны этой игры используют
её собственный шрифт из `font0.bin`.

`tools/analyze_jar.py` читает предоставленный JAR, проверяет CRC и SHA-256,
сохраняет все файлы и разбирает исходный байткод в `game/data/classes.json`.
Формат индексов подтверждён оригинальным `n.a(String)[I`: little-endian число
записей, signed byte номера контейнера и unsigned short смещения; -1 обозначает
границу контейнера. Все 661 извлечённый блок возвращаются в контейнеры побайтово.
175 блоков maps — число ресурсов индекса, а не утверждение о количестве уровней.

`OEVM` исполняет исходные инструкции, сохраняет ссылки на объекты, обработчики
исключений, состояние потоков и позиции в байткоде. `OEJavaNative` обслуживает
внешние Java ME API. `OEMidpGraphics` выводит исходный экран 352×416.
`OEGameSession` запускает `App`, передаёт кнопки и управляет жизненным циклом.
`main.gd` масштабирует экран с сохранением пропорций и добавляет экранные кнопки.
`OEPresentationState` читает оригинальные меню `w.a:[Lt;`, флаги, текстовые
таблицы и аргументы подстановки. Он не исполняет игровые методы и не меняет
состояние. Современные кнопки меню отправляют оригинальные события клавиатуры.
Classic и Remastered используют одну сессию, общий интерфейс и один snapshot.
Первый Remastered — GPU-обработка исходного мира; будущая переработка сцен
не должна подменять карты, бой, ИИ или квесты.

Отдельное имя каталога пользовательских данных исключает пересечение сохранений
с WolfMoon. Реализация RMS пока предполагает одну запись в каждом store — именно
так работают просмотренные пути сохранений `o.java`; совместимость полным
сценарием сохранения и загрузки ещё не подтверждена.

Звук: все исходные MIDI преобразованы Gervill в WAV, проигрыватель поддерживает
несколько независимых голосов. Состояния Player и восстановление музыки после
snapshot требуют дальнейшей проверки.

Известные ограничения платформы: доступная Java-память
моделируется фиксированными значениями, вибрация отключена, внешние ссылки
записываются в диагностическое поле. Неизвестный API останавливает исполнение
с явной ошибкой. Паритет с независимой JVM ещё предстоит подтвердить.


## Слой приключения

`OEJavaNative.draw_rgb` запоминает регион, нарисованный исходным массивом `k.m`,
до наложения старого интерфейса. Полный clip обязателен; неполный кадр не
становится новым эталоном мира. `world_surface` и revision находятся в
`screen.extra`, поэтому входят в существующий граф snapshot без нового формата.
При загрузке старого сохранения без этого поля используется прежний кадр до
следующей полной исходной отрисовки мира.

`OEPresentationState.hud/reader` читают поля с дескрипторами: `v.b:Lq;`,
`v.J:I`, `v.K:I`, таблицы оружия, текста и текущие строки сообщений. UI не
пересчитывает урон, заряды, характеристики или выбор цели. Видимость здоровья
цели повторяет предикаты `e.l()V`. Вступление читает `a.f`, `a.n`, `af/ag/aQ`;
сообщения — `a.b`, таблицу строк `[S`, позиции `av/as/au/ap`, флаги `at`.
Кнопки продолжают посылать исходные события; варианты выбора не переименовываются
произвольно в «Да/Нет» (в оригинале бывают, например, «Закончить/Украсть»).

`OEAdventureHUD` и `OEReaderPanel` — общие для обоих рендеров. Shader не применяется
к тексту или HUD. В специальных состояниях, которые ещё не перенесены, остаётся
исходный растр. Полная замена всех экранов остаётся обязательной задачей.

`OEFontHelpers` ускоряет только чистый поиск индексов глифов и русский character
mapping. `vm.fast_font=false` оставляет исходный путь для проверок. Сравнение
проводится с исполняемым оригинальным байткодом внутри VM, включая полные кадры
и snapshot пяти меню; это не заменяет будущий независимый JVM oracle.

## Проверенные ускорения 0.0.3

Рендер имеет точные GDScript-эквиваленты шести горячих методов класса `k`.
Они работают с теми же Java-массивами и полями. `fast_render=false` включает
исходный путь. Font painter сохраняет байтовые метрики и Graphics-операции;
особые пути оставлены в оригинале. Распаковка использует небольшие block
intrinsics на проверенных обратных переходах двух исходных циклов. Регистрация
хранится в metadata метода, исключённой из snapshot; native блок воспроизводит
живые locals и точку выхода. Поиск описаний возвращает оригинальные объекты.

`frame_budget_us` ограничивает всю порцию VM и сохраняет справедливый порядок
продолжения потоков. Он относится к планировщику платформы, а не к игровым
правилам. Для сравнений установлен 0; тест игровых действий держит виртуальные
часы неподвижными до завершения очередной вычислительной работы.
Полная карта проверок и ограничения: `PERFORMANCE.md`.

## Геометрия и браузерный raster, 0.0.8

`OECompiledGeometry` генерируется из проверенного закрытого набора байткода
классов k/l. Ввод, игровые события, бой и перемещение остаются в оригинальном
потоке. Доступ к полям сохраняет дескрипторы; массивы не подменяются копиями.
`fast_geometry` и `render_helpers.raster.enabled` выключаются независимо для A/B.

`OEWebRaster` накапливает команды для числового JS raster. Между порциями VM
`k.m.data` может отставать от отложенной картинки. Поэтому чтение/запись Java
массивов (в том числе в сгенерированных методах), System.arraycopy, drawRGB и
snapshot имеют барьеры публикации. Любой новый native-код, который читает или
меняет массив, обязан вызвать before_access до доступа. Проверки, читающие
`.data` напрямую вне VM, сначала вызывают sync. Запись инвалидирует готовый
RGBA Image и кэши исходных массивов. release_state/discard удаляет отложенную
работу до очистки объектов прежнего snapshot.

Обычный Web drawRGB использует готовое RGBA-изображение, сохраняя исходный
ARGB-массив и world_surface. Неподдержанные диапазоны/варианты идут прежним путём.
Native остаётся переносимым эталоном. Сравнение двух путей внутри нашей VM
не заменяет независимый JVM-эталон и полное прохождение.

В интерфейсе виден номер сборки. Только `?perf=1` включает браузерный отчёт
задержки. Игра в фоне приостанавливает вычисления, сбрасывает удержание ввода;
тестовый режим управляет виртуальными часами самостоятельно.
